NUTRIORDER AI — PROJECT OVERVIEW
================================

PROJECT INTRODUCTION
--------------------
NutriOrder AI is a Tamil Nadu-focused restaurant menu, ordering, and food-discovery web application. It combines restaurant menu browsing, customer accounts, cart and order management, NutriBot (a Retrieval-Augmented Generation food assistant), and NutriMatch (a preference-based food recommendation engine).

The application is built using HTML, CSS, JavaScript, Python, Flask, and SQLite, with optional Google Gemini and Chroma integrations.

It is an evolving development and demonstration prototype, not a production-ready medical or restaurant commerce service.

Nutrition values on seeded sample dishes may be estimates. Newly added Tamil traditional food records are reference-only until restaurants confirm their recipes, prices, images, availability, allergens, and nutritional information.

TECHNOLOGY STACK
----------------

Frontend:
- HTML5 pages in frontend/, admin/, and bakery/.
- CSS3 styles in css/style.css.
- Browser-based JavaScript in js/.
- No frontend framework or package build step is required.
- Can be served using VS Code Live Server or Python's static HTTP server.

Backend:
- Python 3.10+.
- Flask REST API in backend/app.py.
- Flask-CORS for local frontend-to-backend communication.
- SQLite database, normally nutriorder.db at the project root.
- Werkzeug password hashing.
- Flask sessions and HTTP-only/SameSite cookies for prototype authentication.

AI and Retrieval:
- RAG implementation in rag/chatbot.py.
- Optional indexing implementation in rag/ingest.py.
- Curated Markdown and TXT knowledge documents in rag/documents/.
- Local keyword retrieval without external AI credentials.
- Optional semantic retrieval using LangChain and ChromaDB.
- Optional Google Gemini integration for grounded answer generation and embeddings.
- Gemini requires GEMINI_API_KEY on the backend.
- Basic menu browsing, SQLite operations, keyword retrieval, and deterministic NutriMatch scoring work without Gemini.

MAIN FEATURES
-------------

1. RESTAURANT MENU AND FOOD ORDERING
------------------------------------
- Retrieves food records from SQLite through GET /api/foods.
- Supports text-based food search.
- Supports category filtering.
- Supports vegetarian, non-vegetarian, and egg-based filters.
- Supports budget filtering and sorting.
- Displays individual food details.
- Supports adding food items to a browser-local cart.
- Allows customers to submit orders and view order history.
- Uses actual database prices rather than trusting client-submitted prices.
- Blocks pending and unavailable food records from being ordered.
- Displays missing nutritional values as unavailable rather than inventing values.

Food Images:
- 16 seeded sample restaurant offers use representative local images stored in images/.
- Image records are not marked as restaurant-verified.
- Pending traditional dishes use a fallback illustration.
- Pending records do not have confirmed exact-dish photos.

2. NUTRIBOT — RAG-BASED AI FOOD ASSISTANT
----------------------------------------
Page: frontend/chatbot.html

NutriBot is a food-information assistant that combines live restaurant menu data with curated local knowledge documents.

Core functionality:
- Retrieves current menu information from SQLite.
- Searches Markdown and TXT knowledge documents.
- Provides structured food information.
- Supports named food queries.
- Provides food ingredients and preparation information when available.
- Provides nutritional information when available.
- Provides condition-specific food-suitability summaries with appropriate uncertainty.
- Displays warnings and data verification status.
- Uses source-based fallback responses when external AI services are unavailable.

Named Food Responses:
Can return structured food cards containing:
- English food name.
- Tamil food name.
- Food category.
- Ingredients.
- Preparation notes.
- Available nutritional information.
- Data verification status.
- Relevant warnings.

Health-Related Responses:
Can provide general food-suitability information for questions involving:
- Diabetes and blood sugar.
- Blood pressure.
- Weight gain and weight management.
- Heart-health considerations.
- Other food-related health questions.

Safety and Data Handling:
- Missing nutrition values remain unknown.
- Missing ingredients are not invented.
- Unknown allergens are not treated as safe.
- Missing sodium information is not estimated without evidence.
- Food recommendations are informational, not medical prescriptions.

API Endpoints:
- POST /api/chat
- POST /api/nutribot/chat

Optional AI Integration:
- Gemini can generate grounded responses when configured.
- Chroma can provide semantic document retrieval.
- Local keyword retrieval continues to work without Gemini or Chroma.

3. NUTRIMATCH — PERSONALIZED FOOD RECOMMENDATIONS
-------------------------------------------------
Page: frontend/recommendation.html

NutriMatch is a deterministic preference-based food recommendation system.

It uses a multi-step optional questionnaire covering:
- Food goals.
- Health considerations.
- Dietary type.
- Cuisine preferences.
- Allergies.
- Nutrition preferences.
- Taste preferences.
- Meal timing.
- Budget.
- Optional personal measurements.

Recommendation Weights:

Goal                  : 30%
Nutrition Preference  : 25%
Cuisine               : 15%
Taste                 : 10%
Budget                : 10%
Meal Timing           : 10%

Total                 : 100%

Recommendation Process:
- Validates the submitted preference selections.
- Retrieves current food records from SQLite.
- Filters unavailable and pending food records.
- Applies allergy and strict dietary restrictions.
- Checks relevant price, meal, and cuisine conditions.
- Calculates deterministic preference-matching scores.
- Displays suitable matches, alternatives, and items requiring verification.
- May include supporting knowledge-document excerpts.

Safety Rules:
- Allergy and strict dietary restrictions are applied before scoring.
- Unknown allergen declarations require restaurant verification.
- Pending catalog records are never treated as current restaurant offers.
- Preference selections are request-scoped and are not persisted as recommendation profiles.
- Age, height, weight, and activity inputs are not submitted for calorie-target calculations.
- Match scores represent preference compatibility, not medical suitability.

NutriMatch API Endpoints:
- POST /api/nutrimatch/profile
- POST /api/nutrimatch/recommendations
- POST /api/nutrimatch/chat
- GET /api/nutrimatch/foods
- GET /api/nutrimatch/foods/<food_id>
- GET /api/nutrimatch/categories
- GET /api/nutrimatch/filters

- No assumed offer prices.

- reference_pending_restaurant_confirmation

LOCAL DEVELOPMENT SETUP
-----------------------
Requirements:
- Python 3.10 or above.
- pip.
- Git (recommended).
- VS Code (recommended).

Step 1: Install Dependencies

From the project root:

python -m pip install -r requirements.txt

Step 2: Start Flask Backend

python backend/app.py

Default API address:

http://127.0.0.1:5000

Step 3: Start Frontend

Open a second terminal from the project root:

python -m http.server 8000

Alternatively, use VS Code Live Server.

Step 4: Open Application

Home:
http://localhost:8000/frontend/index.html

Menu:
http://localhost:8000/frontend/menu.html

NutriBot:
http://localhost:8000/frontend/chatbot.html

NutriMatch:
http://localhost:8000/frontend/recommendation.html

API Health Check:
http://127.0.0.1:5000/api/test

The database initialization, schema migration, and seed operations run when Flask starts.

The default local CORS configuration allows frontend development origins on ports 8000 and 5500.

DATABASE CONFIGURATION
----------------------
By default, the application uses:

nutriorder.db

This database is located at the project root.

To use another database file, configure:

NUTRIORDER_DB

The value can be an absolute path or a path relative to the project root.

OPTIONAL GEMINI AND RAG CONFIGURATION
------------------------------------
Gemini and semantic retrieval are optional.

To enable Gemini:
1. Create or obtain a Gemini API key.
2. Configure GEMINI_API_KEY in the backend environment or local .env file.
3. Restart the Flask backend.

Example:

GEMINI_API_KEY=your_api_key_here

To build or refresh the optional Chroma index:

python -m rag.ingest

Run the command from the repository root after configuring the required API key.

Important:
- Keep all provider keys on the backend.
- Never expose API keys in browser JavaScript.
- Never commit .env to GitHub.
- Chroma indexing is optional.
- Live menu information is retrieved from SQLite for chat requests.
- Local keyword retrieval remains available without the vector index.

DATA ACCURACY AND SAFETY LIMITATIONS
------------------------------------
- Seeded sample food calories and macronutrients may be estimates.
- Traditional Tamil dish references are not necessarily restaurant offerings.
- Missing nutrition values must remain unknown, not zero.
- Missing prices must not be treated as free food.
- Local representative photos are not exact-dish verification.
- Recipes, serving sizes, ingredients, allergens, and cross-contact information require restaurant confirmation.
- Food availability must be confirmed using current restaurant data.
- NutriBot does not diagnose medical conditions or prescribe treatment.
- NutriMatch does not calculate clinical nutritional targets.
- Neither NutriBot nor NutriMatch guarantees allergy safety.
- Customers must confirm allergy and cross-contact risks directly with restaurant staff.
- Demo credentials must never be used for real accounts or public deployments.
